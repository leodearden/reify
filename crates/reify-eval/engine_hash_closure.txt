# engine_hash_closure.txt — reify-eval's build+normal (exclude-dev) dependency closure.
#
# Purpose
#   ENGINE_VERSION_HASH narrows its Cargo.lock contribution to ONLY the resolved
#   (name, version) pins of the crate NAMES listed below — reify-eval's own
#   build + normal (dev-EXCLUDED) transitive closure. This stops an unrelated
#   dep bump elsewhere in the 716-package workspace lockfile from invalidating
#   the persistent FEA cache, while still invalidating on any bump that can
#   change shipped-engine semantics. See docs/prds/merge-gate-compile-cost.md
#   §3 W4 / §5 C4.
#
# Soundness (must OVER-APPROXIMATE the true closure — ⊇)
#   Excluding dev-only deps (e.g. the gmsh-sys FFI, linked only in reify-eval's
#   #[cfg(has_gmsh)] test binaries) is sound: those never run in the persisted
#   engine, and mesh-input changes are captured by the FEA INPUT hash, not the
#   engine hash. The drift guard tests/infra/test_engine_hash_closure.sh asserts
#   this manifest ⊇ the freshly-recomputed closure (any missing member FAILs).
#
# Canonical regeneration command (MUST stay byte-identical to the drift guard):
#   cargo tree -p reify-eval -e no-dev --prefix none \
#     --target x86_64-unknown-linux-gnu --frozen -f '{p}' \
#     | awk '{print $1}' | sort -u
#
# One name per line, sorted-unique. Lines beginning with '#' and blank lines
# are ignored by parse_closure_manifest (crates/reify-eval/src/engine_hash_algo.rs).
