#   Lists repo-relative paths that load-bear the --scope all verify pipeline

# Format:

#   Consuming code: scripts/verify-pipeline-guard.sh

#   - scripts/gen-nextest-config.sh: generates .config/nextest.toml profile
#     content; changing it changes the nextest config used by all test passes.
#   - .config/nextest.toml: nextest configuration; profile changes alter which
#     tests are run and how.
#
# NOTE: The sourced libs (occt-scope-lib.sh, release-scope-lib.sh,
# affected-crates-lib.sh, lib_test_semaphore.sh, cpu-admit.sh) are NOT listed

# for future additions.  Listing them here too would be harmless but redundant.

# NOTE: The EMITTED GATE SCRIPTS are likewise NOT listed here (task 6320).

#   ONE QUALIFICATION on "do not add one" — MUCH NARROWER SINCE TASK 6426, so
#   do not add a row on the strength of the old advice. Auto-derivation is now a
#   UNION: a grep of verify.sh's SOURCE TEXT for literal paths in
#   add()/add_tool() statements, PLUS the paths named by the RESOLVED plan that
#   one canonical widest --print-plan invocation prints. A plan line assembled
#   through a VARIABLE:
#
#       _cmd="./scripts/new-gate.sh"      # <- invisible to the source-text half
#       add_tool "$_cmd"                  #    but NAMED in the resolved plan
#
#   is therefore auto-derived after all and needs NO row here, PROVIDED the
#   canonical invocation reaches it. Inspect that half alone with
#   `bash scripts/verify-pipeline-guard.sh --list-plan-derived`.
#
#   WHAT STILL NEEDS A ROW is the narrow residual: a variable-assembled plan
#   line in a branch of build_plan the canonical invocation NEVER TAKES. Neither
#   half sees it — the source-text half because the path is behind a variable,
#   the plan-derived half because the line never executes — so it is silently
#   fast-path eligible with no red signal anywhere. If you must wire a gate that
#   way, add a row here and say why. Prefer, in order: a literal path; a branch
#   the canonical invocation reaches; a row here as the last resort.
