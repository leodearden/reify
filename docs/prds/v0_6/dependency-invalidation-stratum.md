## 2. Problem (re-verified at `8e6ffcac9d`)

One strongly connected component holds 24 of them (95,192 raw lines): cache, cell_commit, compute_persist, demand, deps, dirty, engine_admin, engine_build, engine_compute, engine_edit, engine_eval, engine_fixpoint, freshness_walk, geometry_ops, invariants, journal, observed_demand, realization_content, realization_staleness, resolve_order, shell_extract_compute, undef_tracer, unfold, warm_pool. Reproduced this session with the review's modgraph rule. The dependency/cache stratum would sit below the engine-phase modules but for upward references that fetch pure predicates defined inside engine files: `deps` → `geometry_ops::is_geometry_query_call`; `invariants` → four `geometry_ops` predicates; `resolve_order` → `engine_eval::{expand_solver_position_expr, is_optimized_userfn_cell}`; `realization_staleness` → `engine_build::{sub_refs_in_op, compute_realization_upstream_values_hash_from_ops}`; `realization_content` and `shell_extract_compute` → contract types through the `engine_compute` re-export block. Nothing in the gate measures intra-crate module cycles (heuristic 9 layering; heuristic 13).
2. **Three dependency walks** in `deps.rs`: `ReverseDependencyIndex::build_from_graph_and_fields`, `build_trace_map_and_fields`, and `DependencyMap::from_graph`. The first two must agree and are built separately at 5 paired production sites (engine_eval 1, engine_edit 2, engine_purposes 2) plus a reverse-only rebuild (`invalidate_realization_dirty_cone`). They already differ: Compute nodes get reverse edges #6/#10 but no forward entry. `DependencyMap` (consumed only by `Engine::trace_undef_causes` and the dead `cache::dirty_set`) has a third semantics: it reads Auto cells' `default_expr`, ignores constraints, realizations and composed fields, and dedups. Agreement is pinned edge-class by edge-class by tests named `*_both_directions` (heuristic 11 SPOT).
3. **Two dirty-cone bodies.** `dirty::compute_dirty_cone` and `compute_dirty_cone_with_realizations` repeat the ValueCell BFS with the edge-#12 Compute→output expansion. Only the realization frontier dispatches on `NodeId` exhaustively; both ValueCell loops use `if let` chains, so a new `NodeId` variant is a silent leaf. The `_with_realizations` variant has one production caller, which passes an empty ValueCell seed set (heuristics 11, 10, 1).
4. **Dead invalidation peers in `cache.rs`**: `dirty_set` (zero callers; unused `_graph`/`_values`; doc describes behaviour it lacks), `check_early_cutoff` and `compute_input_hash` (test-only), `DependencyMap::topological_order` (called only by `dirty_set` and deps tests), and the free `derive_output_freshness` (test-only; production uses `derive_output_freshness_for_node_with_cause`) (heuristics 11, 6, 1).

The production compute-completion site carries `TODO(#5023): async completions must invalidate dependents (propagate_freshness_only)` after `complete_compute_dispatch_atomically`. **Ruled 2026-10-12: deleted;** async completions mark dependents dirty through the single dirty cone (heuristic 6).
6. **Value-cell identity hash written inline 8 times.** `ContentHash::of_str(&format!("{}", id)).combine(default_expr.map(content_hash).unwrap_or(ContentHash(0)))` appears at 6 sites in `EvaluationGraph::from_templates` and 2 in `engine_edit` (the collection-count re-elaboration and its twin); `ValueCellNode` has only public fields and no constructor; `ConstraintNodeData` is built literally 4× in graph.rs, 2× in engine_edit, 1× in engine_purposes. The cold and edit paths must hash byte-identically (the INV-EVAL-4 class) and nothing links them but copy discipline. `from_templates` is one 424-line function nested 13 levels deep (heuristics 11, 4, 10).
7. **The Sub-operand resolution rule is implemented twice.** `realization_staleness::sub_consumers_the_reverse_index_drops` re-implements `deps::{resolve_geom_sub_edge, resolve_sub_ref, resolve_sibling_ref}` with its own exporter map and `split_once('.')`, kept in step by the mirror test `the_dropped_operand_rule_agrees_with_the_reverse_index` (heuristics 11, 12).

9. **Demand pass-throughs** (weakened, re-read with its skeptic note). `Engine::add_demand` / `remove_demand` have zero callers anywhere and skip the prune step `set_demand_selective` performs; the inspection methods `demand_cone_size`, `demand_is_demanded`, `observed_demand_is_demanded`, `observed_demand_cone_size` are test-only. The property the ruling wants, downward imports, is kept as the **checkable** form: the new homes import no reify-eval module inside the measured SCC, and only crates below reify-eval in the crate DAG (`reify_core`, `reify_ir`, `reify_compiler`, `reify_expr`). **Recommended (B):** three homes by purpose (heuristic 6, one sentence without "and"; heuristic 1, a name that does not lie):
  - `expr_classify.rs` — classifications over `CompiledExpr`: the five geometry predicates and `is_optimized_userfn_cell`, plus the constants and name maps they read (below).
  - `realization_inputs.rs` — what a realization's ops read: `sub_refs_in_op`, `compute_realization_upstream_values_hash_from_ops`, and its helper `arg_contains_cross_sub_geometry_ref`. **[Amended 2026-10-20, retro-critic R13]** The helper is not private: `engine_build` calls it at five more production sites, so it is `pub(crate)` in `realization_inputs.rs` and `engine_build` imports it downward (premise and residual re-verified).
  - `structural_query.rs` (existing, zero `crate::` edges) — `expand_solver_position_expr`, which is only a sequence of three `structural_query` passes.
  Ruled (B) by the lead, amending the original ruling's "imports only reify_ir/reify_core" (program doc §Lead amendments). Option A (one `expr_classify.rs` importing reify_compiler/reify_expr too) was not taken.
- **D2 — The symbolic-selector name map keeps one home.** `is_symbolic_eval_wired_selector_ctor` reads `symbolic_eval_helper_for_name`, a name → private `TopologySelectorHelper` map shared with the dispatcher `try_eval_symbolic_topology_selector` (its doc names it the single source of truth). Moving the predicate must not fork that map. `expr_classify` gains `SymbolicSelectorCtor` (one variant per kernel-free ctor name, `from_name(&str) -> Option<Self>`); `geometry_ops` keeps `TopologySelectorHelper` private and maps `SymbolicSelectorCtor → TopologySelectorHelper` with an exhaustive `match`, so a new ctor name is a compile error until both halves exist. `FEATURE_DATUM_PROJECTION_MEMBERS` moves into `expr_classify` too; geometry_ops's datum-projection dispatch imports it downward. (S8 later derives these name sets from `reify-builtins` rows and moves the datum-projection table to reify-ir, so the new home is S8's starting point, not its end state.)
- **D3 — One forward walk; the reverse index is its inversion.** `deps` gains `DependencyGraph` (§5.2): built once by `DependencyGraph::from_graph_and_fields(graph, fields)`, it holds the forward `DependencyTrace` of **every** node kind, including `NodeId::Compute` (its `value_inputs` / `realization_inputs`). `ReverseDependencyIndex` is produced only by `DependencyGraph::reverse()`, an inversion with no node-kind knowledge of its own. **[Amended 2026-10-20, retro-critic R13]** Two named exceptions: `ReverseDependencyIndex::default` stays for the `engine_eval` placeholder, and `add`/`add_realization` stay `#[cfg(test)] pub(crate)` so the hand-spliced test indices (dirty.rs, including the R0↔R1 realization-cycle fixture B6 replays; freshness_walk.rs and gating.rs until ζ deletes them) keep compiling. `DependencyGraph::from_traces(HashMap<NodeId, DependencyTrace>)` is added as a `#[cfg(test)]` constructor for synthetic-input tests (undef_tracer's `make_dep_map` tests). Full privatisation of `add`/`add_realization` moves after ζ. The scheduler-facing trace map is a named projection, `DependencyGraph::schedulable_traces()`, which **excludes `NodeId::Compute`**: today's trace map has no Compute entries because compute nodes are dispatched inline in the let-cell loops, not scheduled (#4958 owns making them executor steps). The asymmetry the finding found becomes one documented line of code instead of an accident. `build_from_graph_and_fields`, `build_from_graph`, `build_trace_map_and_fields`, `build_trace_map` and `DependencyMap` are deleted; the 5 paired sites become one construction plus two derivations, and the reverse-only rebuild calls `.reverse()`.
- **D4 — The undef tracer reads the unified graph; Auto cells are leaves.** `undef_tracer::trace_undef_causes` takes `&DependencyGraph` and walks ValueCell reads with the same `forward_reachable(start, should_expand)` contract `DependencyMap` offered (moved onto `DependencyGraph`, same sort and cycle guard). Semantic deltas, accepted: an Auto cell's `default_expr` is no longer traversed, because an auto's value comes from the solver, so its default is not a cause (the eval graph already treats autos as solver-owned leaves); composed-field cells (`__field.<name>`) become traversable, because they are in the unified graph. Pinned by γ's behaviour test (§9).
- **D5 — One dirty-cone walker with an explicit policy.** `dirty::dirty_cone(seeds: &ConeSeeds, policy: ConePolicy, reverse: &ReverseDependencyIndex, graph) -> HashSet<NodeId>` (§5.3). `ConePolicy::StopAtRealizations` is today's `compute_dirty_cone` (Realization and Constraint dependents are leaves; realization re-evaluation is decided separately by `realization_staleness`). `ConePolicy::ThroughRealizations` is today's `_with_realizations` (transitive across both frontiers). Both frontier loops dispatch with one exhaustive `match` on `NodeId` through a single `expand(dependent)` step, so a new `NodeId` variant fails to compile at exactly one place. The `invalidate_realization_dirty_cone` caller names what it seeds (`ConeSeeds::realizations(seeds)`), which retires the misnomer.

The formula is byte-identical to today's, so persistent-cache keys and early-cutoff behaviour do not move. **[Amended 2026-10-20, retro-critic R13]** Two more constructions sit outside that set and get their own constructors (esc-8677-3's accepted departures, folded here): `ConstraintNodeData::new(id, label, expr, optimized_target)` computes the standard formula for the two `engine_edit` forall sites that have no `CompiledConstraint` (forall_connect's literal `Bool(true)`, the forall body's rewritten `body_expr`); and three named `pub(crate)` constructors in `graph.rs` keep their deliberately different formulas verbatim, computing them internally — `purpose_let` (`of_str("purpose:{p}:let:{name}")`), `purpose_constraint` (`of_str("purpose:{p}:constraint:{i}")`) and `shell_extract_output(&Value)` (`result.content_hash()`). - **D10 — B + H-lite.** Blast radius is ≥ 3 crates (reify-eval, reify-core, reify-compiler, reify-build-utils, gui/src-tauri), with about 9 mechanisms, and S4/S1/S2/S8 consume the result. The contract (§5) fixes signatures and invariants. The boundary tests (§6) are mostly behaviour-preservation parities, since every change except ζ's and D4's stated deltas is behaviour-preserving.
- **D11 — The ratchet is exact, and it is a cargo test beside the crate-DAG gate.** `scripts/assert-module-scc.py` (stdlib Python 3.12, no third-party dependency) with a committed `scripts/module-scc-baseline.json`, driven by `crates/reify-build-utils/tests/module_scc_ratchet.rs` the same way `crate_dag_assertion.rs` drives `assert-crate-dag.sh`. The check is **set equality** per crate: a grown or new SCC is red (naming every intra-SCC import site that closes it), and a shrunk or vanished SCC is red as a stale baseline that must be lowered in the same diff. So "shrinks monotonically" is recorded, never silent. Placement keeps the ratchet out of every verify-pipeline file (S18) and out of `tests/infra` discovery and its manifest (S19). The cost is that per-task lanes run it only when reify-build-utils is affected; the merge gate (`--scope all`) always runs it. The PTODO ratchet accepts the same latency trade (verify.sh's run_all.sh merge-tier comment).

## 5. Contract (H)

### 5.1 Module-SCC rule and baseline (INV-ARCH-1)

- **Universe:** every `[workspace] members` entry of the root `Cargo.toml` (read with `tomllib`) that has a `src/` directory, minus the crates named in the baseline's `excluded` map (initially `{"reify-compiler": "glob imports hide edges until S7 κ; S7 ξ adds the rows"}`). An excluded crate is not measured and a baseline row for it is rejected; removing the exclusion is S7 ξ's one-time, named change. A top-level module is a `src/<m>.rs` file or a `src/<m>/` directory (all its files belong to `<m>`), excluding `lib.rs`/`main.rs`.
- **Edges** `m → n` (m ≠ n, both top-level modules of the same crate): an occurrence of `crate::n` or a name `n` inside a `crate::{…}` list, in production text of `m`'s files.
- **Production text** = the file minus (1) lines whose first non-blank characters are `//` (doc and line comments), (2) every `#[cfg(test)]` / `#[cfg(all(test, …))]`-attributed item, brace-matched (not cut at the first one), and (3) entire top-level modules whose `mod` declaration in the crate root is `#[cfg(test)]`-gated.
- **Measurement:** Tarjan SCCs of size ≥ 2 per crate; each recorded as its sorted member list.
- **Baseline file:** `scripts/module-scc-baseline.json`, `{"schema": 1, "excluded": {"<package name>": "<reason>"}, "crates": {"<package name>": [["a","b"], …]}}`, sorted, with crates that have no SCC omitted.
- **CLI:** `assert-module-scc.py check [--root DIR] [--baseline FILE]` exits 0 iff measured == baseline. On mismatch it exits 1 and prints one line per violation: `GREW <crate>: {members}` followed by each closing import as `<file>: <module> -> <module>` (no line numbers in the baseline; they are printed only for the reader), or `STALE <crate>: baseline {old} measured {new} — lower the baseline`. `assert-module-scc.py print` emits the current measurement in baseline format (used to lower the baseline). A missing or unparseable root `Cargo.toml` or baseline fails closed with a named message.

### 5.2 `deps::DependencyGraph`

```rust
pub struct DependencyGraph { /* forward: HashMap<NodeId, DependencyTrace> — every node kind */ }
impl DependencyGraph {
    pub fn from_graph_and_fields(graph: &EvaluationGraph, fields: &[CompiledField]) -> Self;
    #[cfg(test)] pub(crate) fn from_traces(forward: HashMap<NodeId, DependencyTrace>) -> Self; // R13: synthetic-input tests
    pub fn trace(&self, node: &NodeId) -> Option<&DependencyTrace>;
    pub fn reverse(&self) -> ReverseDependencyIndex;             // pure inversion
    pub fn schedulable_traces(&self) -> HashMap<NodeId, DependencyTrace>; // excludes NodeId::Compute
    pub fn forward_reachable(&self, start: &ValueCellId,
                             should_expand: impl Fn(&ValueCellId) -> bool) -> Vec<ValueCellId>;

```
Invariants: for every edge `n reads c` in `forward`, `reverse().dependents_of(c) ∋ n` (and the realization-keyed twin), and nothing else is in `reverse()`. `schedulable_traces()` equals today's `build_trace_map_and_fields` output on every graph. `reverse()` equals today's `build_from_graph_and_fields` output on every graph whose compute nodes are already inserted. That carries over the edge-#10 admissibility rule `invalidate_realization_dirty_cone` documents, unchanged. `ReverseDependencyIndex` keeps its read API (`dependents_of`, `realization_dependents_of`). **[Amended 2026-10-20, retro-critic R13]** Its `add`/`add_realization` stay `#[cfg(test)] pub(crate)` (test edge-splice) until after ζ, when they become private to `deps`; `ReverseDependencyIndex::default` stays for the `engine_eval` placeholder.

### 5.3 `dirty::dirty_cone`

```rust
pub struct ConeSeeds { cells: HashSet<ValueCellId>, realizations: HashSet<RealizationNodeId> }
impl ConeSeeds { pub fn cells(..) -> Self; pub fn realizations(..) -> Self; pub fn both(..) -> Self; }
```

Invariants: seeds are not in the result (roots), as today. `dirty_cone(cells(s), StopAtRealizations, …) == compute_dirty_cone(s, …)` and `dirty_cone(realizations(r), ThroughRealizations, …) == compute_dirty_cone_with_realizations(∅, r, …)` on every fixture graph. `DemandRegistry::from_roots(roots: impl IntoIterator<Item = NodeId>, full_scope: bool, graph: &EvaluationGraph) -> Self`: the cone is always the backward closure of `roots` over `graph`; there is no state in which a registry value's roots and cone disagree. **[Amended 2026-10-20, retro-critic R13]** The Engine names the three places that state is crossed (D9): the full_scope transition (rebuild from roots against the current graph, or keep `full_scope` outside the registry value), the pre-eval state (the Engine keeps the requested roots and builds the registry at first eval), and the rebuild sites (structural edit, purpose activation, cold eval as `from_roots(self.demand.roots(), …, &graph)`), each an eager closure whose cost D9 states.
