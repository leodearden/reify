## 2. Problem (survey §H2, confirmed by code re-verification)

`engine_build.rs` (21,998 lines) is the most fix-patched file since May. Verified on `bc3771221f`:

1. **Version-id handling has three conventions.** Raw allocate-and-bump duplicated verbatim at **5 sites**, each allocating BOTH ids: `concurrent.rs:170–173`, `engine_eval.rs:2935–2938`, `engine_eval.rs:3816–3819`, `engine_edit.rs:856–859`, `engine_edit.rs:2424–2427`. A private reader `current_eval_version()` (`engine_build.rs:7993`, panics if `eval_state` unset). An independent reimplementation `VersionId(self.next_version_id.saturating_sub(1))` at `engine_admin.rs:2211` (doc :2197) with **different edge-case semantics** (saturates to 0 pre-eval vs panic) — engine_admin cannot call the private reader.
2. **~24-parameter `execute_realization_ops` signature** (`engine_build.rs:6074–6162`) caused 11+ "thread new arg through every call site" fix commits. The output side was solved by `RealizationOutputs<'a>` (task 3119, `engine_build.rs:117–154`); the input side was not. 4 production call sites (:2826, :3708, :4702, :5761), the `DispatchTestState` wrapper (:12104–), and 3 wrapper-bypassing test call sites (:14182, :14349, :14502) all churn on each orthogonal addition.
3. **The ~200-line cache-hit short-circuit** (`engine_build.rs:~6188–6320`, "Task 2874, step-8" block) must *remember* to emulate every side effect of the main op loop — obligations implicit, not typed. Three separate bugs clustered there (4349 double-insert; 3437 false-hit on intermediate realizations; the reviewer_comprehensive #1 perf regression). The 4349 fix is a **defensive eviction workaround** (`feature_tag_table.remove` / `topology_attribute_table.remove` at :6294–6295); the principled fix (KernelHandle re-key) is open **task #4351**.
4. **Per-build reset invariants are tribal.** Hand-copied table-reset blocks at 4 entry points — gated in `build_snapshot` (:2745–2747) and `build_with_geometry_output` (:3487–3489), ungated in `tessellate_realizations` (:5120–5126) and `tessellate_snapshot` (:10122–10127) — plus `realization_handles.clear()` at :2645/:3306 (build surfaces only) and `achieved_repr_tol.clear()` at :5126/:10127 (tessellate surfaces only). No structural guarantee for a 5th table or entry point.

## 4. Resolved design decisions

- **D1 — allocator shape.** `Engine::allocate_snapshot_version(&mut self) -> (SnapshotId, VersionId)`: all 5 raw sites allocate BOTH ids in lockstep (verified §2.1), so the helper allocates the pair; defined in `engine_admin.rs` (beside the field initialisers, :288). Version-id **reads** get one API family: `current_eval_version()` flips to `pub(crate)`; the `engine_admin.rs:2211` saturating formula becomes an explicit, documented choice (δ decides between (i) a named `last_allocated_version()` reader beside the allocator, documented "VersionId(0) before the first allocation", preserving today's warm-pool-journal behavior — the default recommendation — or (ii) routing through `current_eval_version()` with explicit pre-eval handling; either preserves INV-BUILD-2 "reads through exactly one API each").
- **D2 — adopt #4351, don't refile.** #4351 exists, is pending with committed progress, and was re-scoped 2026-06-24 to **TopologyAttributeTable-only** (the FeatureTagTable half is superseded by #4827's outright deletion). This PRD wires real edges around it (η upstream of it; θ and κ downstream of it) instead of filing a duplicate re-key task. Consequently the brief's "re-key FeatureTagTable/TopologyAttributeTable" resolves as: FeatureTagTable → **deleted** (#4827); TopologyAttributeTable → **re-keyed** (#4351).
- **D3 — extraction after the FeatureTagTable deletion.** η (extract `probe_realization_cache`) depends on #4827: the short-circuit's `feature_tag_table.remove` line, the `RealizationOutputs.feature_tag_table` field, and the feature-tag half of the 4349 collision tests (:18931) are all deleted by #4827. Extracting first would force #4827 to chase moved code and carry a doomed table through the new helper's contract.
- **D4 — probe extraction consumes the input struct.** η depends on ζ (RealizationOpsInput) so the extracted `probe_realization_cache(...) -> Option<CacheHit>` takes struct-shaped inputs, not another positional cascade. ζ is one focused task, not incremental (brief-ratified).
- **D5 — per-surface reset classification (refinement of the brief; the load-bearing correction of this PRD).** The brief says "call `reset_per_build_state` unconditionally at all 4 entry points". Verified against main, a *naive full-union* reset would **break production**: `crates/reify-cli/src/main.rs:555–640` deliberately sequences `build()` (populates `realization_handles`; does NOT touch `achieved_repr_tol`) then `tessellate_realizations()` (populates `achieved_repr_tol`; does NOT clear `realization_handles`) so a module carrying both `RepresentationWithin` and geometric `Conforms`/DFM gets real verdicts for each — the comment block documents this reliance explicitly. Resolution: `reset_per_build_state(surface: BuildSurface)` is still ONE method called unconditionally at all 4 entry points, with an **exhaustive `Engine`-field destructure** so a new field forces a compile-time decision; but the classification is per-surface-explicit: **reset-every-surface** = `topology_attribute_table`, `swept_kind_table`, dispatch tallies (`reset_dispatch_tallies`, :2571, folds in), `geometry_revalidation_slow_path` counter (and `feature_tag_table` until #4827 lands — the destructure arm simply disappears on rebase); **reset-on-build-surfaces** = `realization_handles`; **reset-on-tessellate-surfaces** = `achieved_repr_tol`; **must-survive (never sweep in — regression if you do)** = `realization_cache` (task 2874's whole point), `warm_pool`, `morph_source` (`lib.rs:~982–990`), persistent-cache state/counters (`persistent_cache_dir`/`persistent_hit_count`/`persistent_miss_count`, `lib.rs:1055–1065`), compute/solver/optimization registries, and all eval-state/snapshot/journal fields. The previously **gated** table resets (build surfaces gated on a registered default kernel) become unconditional — safe because tables are only populated under a registered kernel; ι characterizes this. Each classification is written next to its destructure arm with a one-line rationale; the CLI interleaving gets a pinning test (leaf signal (d)).
- **D6 — eviction retirement is fail-closed.** After #4351, the defensive `topology_attribute_table.remove(cached_handle.id)` in the probe is a no-op by construction. θ removes it and replaces it with a `debug_assert!` that the KernelHandle-keyed table has no entry for the cache-served handle (the #3226 spec, now assertable without cross-kernel false positives) — enforcing INV-BUILD-3/INV-GEO-2 loudly per the fail-closed posture (decisions ledger #5). The `#3226`-era eviction rationale docs on `TopologyAttributeTable::remove` (`reify-ir/src/geometry.rs:4633–4635`; the FeatureTagTable twin at :4072–4074 dies with #4827) are updated; if `remove()` loses its last production caller, θ decides keep-for-API vs delete with a breadcrumb.
- **D7 — grep gate as a Rust integration test.** ε lands `crates/reify-eval/tests/version_id_discipline_gate.rs`: scans `crates/reify-eval/src/**.rs` and fails on `next_version_id` / `next_snapshot_id` arithmetic or reads outside the allocator/reader definitions (allowlist: the defining module's impl block; constructor initialisers; an explicit `// version-id-gate: allow — <reason>` escape comment mirroring the `ptodo:allow` precedent, needed e.g. for `concurrent.rs:227`'s setup-restore *assignment* if the concurrent stack still exists). Runs in every nextest invocation — no verify-pipeline file changes.
- **D8 — B + H-lite (G5).** The PRD touches the multi-kernel load-bearing seam, so an H component is included: §5's contracts + the two-way boundary tests that already exist and move with the extraction (producer-facing: the 4349 cross-kernel collision tests, `engine_build.rs:18869–19100`; consumer-facing: κ's real-kernel end-to-end). No new cross-crate seam is introduced, so a full contract-doc PRD is not warranted.
- **D9 — sequencing per the decisions ledger.** Hardening first; the unified DAG executor consumes the result later (no edge — deferred PRD). Wide-lock engine_build.rs tasks (ζ, η, ι) get **high** priority so module-lock parking pushes them through (ledger #9).

## 5. Contracts (H component)

### 5.1 `probe_realization_cache` (INV-BUILD-3)
```rust
struct CacheHit { handle: KernelHandle, resolved_repr: ReprKind }
fn probe_realization_cache(/* struct-shaped subset of RealizationOpsInput + cache + outputs views */) -> Option<CacheHit>
```
Invariants (all pinned by unit tests moving/landing with η):
- Probes ONLY when `is_terminal_realization && demanded_tol.is_some() && realization_name.is_some()` (the 3437 intermediate-false-hit fix and the named_steps contract).
- Primary probe at `(entity, demanded_repr, tol)`; on miss with `demanded_repr != BRep`, fallback probe at `(entity, BRep, tol)` (the perf-regression fix; load-bearing for the Stl/Obj export path).
- On hit, the helper performs the FULL observable side-effect set of a cold-path success for a terminal realization: push `step_handles`, write `named_steps[name]`, write `produced_repr_out = Some(resolved_repr)` (= the cache key's repr), leave dispatch counters at their entry values, return before the op loop. **The side-effect set is the contract**: any new obligation added to the cold path must be added here or explicitly documented as cold-only — the extraction makes the obligation set a reviewable unit instead of a mid-function region.
- Collision behavior: pre-#4351, the defensive eviction (documented interim trade-off); post-θ, a fail-closed `debug_assert!` of table-emptiness at the KernelHandle key.

### 5.2 Version/snapshot-id allocation (INV-BUILD-2)
- `allocate_snapshot_version(&mut self) -> (SnapshotId, VersionId)` is the ONLY writer of `next_snapshot_id`/`next_version_id` (setup-restore assignments allowlisted explicitly).
- Reads: `current_eval_version()` (pub(crate); panics before first eval — deliberate, documented) and the δ-decided companion for the "most recently allocated, 0 pre-eval" semantics. Divergence between the two is documented at both definitions.
- ε's gate makes the discipline self-enforcing.

### 5.3 `reset_per_build_state` (INV-BUILD-1)
Per-surface classification table in D5. Enforcement: exhaustive destructure (compile error on unclassified new field) + the (d) CLI characterization pin + existing per-build reset regression tests.
