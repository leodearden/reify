# Damped modal for bonded heterogeneous constructions

**Status:** active — authored + decomposed 2026-08-27. Milestone v0.6.
**Seed:** task #6753 (cancelled at decompose with a pointer here; its content is fully ported into this document).
**Anchors:** cite-by-symbol throughout (no hard `path:line`). Substrate verified empirically 2026-08-27 (probe corpus preserved at the damping-needs investigation session, `study-reify-6753-910676/probes/`; decompose-time fixtures under `tests/prd-gate/fixtures/` are the committed evidence).

## Goal

A `.ri` author designing a bonded multi-material construction — the motivating case is a steel-skin / epoxy-granite-core sandwich — can **predict per-mode damping ratios from the construction itself** (layer thicknesses + per-material loss factors), instead of hand-imposing a global Rayleigh pair. Concretely, after this PRD:

- Materials can carry a loss factor: `structure def MySteel : DampedMaterial + Visual { … param loss_factor : Real = 0.0006 }`.
- A spatially-varying material is authorable via the declarative constructors — `sandwich_material(axis, [(3mm, steel), (16mm, eg), (3mm, steel)])`, `material_zones([...])` — producing `Field<Point3<Length>, AnisotropicMaterial>`. (Raw `fn_field` lambdas are NOT an author surface for this: probed 2026-08-27, parameterized lambda-param annotations don't resolve and lambda-param member access is unsupported — #6871; see Out of scope.)
- `solve_elastic_static` and `modal_analysis` accept such fields on the dims-overload (synthetic-mesh) path, with mesh planes snapped to declared layer interfaces.
- `modal_analysis(field, …, ModalOptions(damping: MaterialDamping(), …))` returns modes whose `Mode.damping_ratio` is the **modal-strain-energy (MSE)** composition ζ_mode = ½·Σ_e η_e·SE_e / Σ_e SE_e — per-element loss factor weighted by that element's modal strain energy.
- Consumer (G1): `prj/printer_v01/printer.ri` `AFrame` — predicts field-panel and pillar ζ from `skin_t`/`core_t`/η, gates the spec's damping thesis in-design, and trades `core_t` on predicted damping instead of folklore. The committed stand-in for that consumer is the `examples/best_practices/` sandwich-damping exemplar (leaf θ), AFrame-shaped by construction.

## Background

The printer frame's design thesis is damping (spec: "damping ratio 5–10× steel" for polymer concrete), i.e. constrained-layer behaviour — but the engine's only damping surface is `NoDamping` / global `RayleighDamping{alpha,beta}` on `ModalOptions`, consumed post-eigensolve by `rayleigh_damping_ratio` and the transient integrator. Every modal number any design produces today is undamped; damping fidelity is zero. The 2026-08-27 investigation (agent-team survey: engineering methods + task/PRD coverage + engine ground truth) established:

- **MSE is the right first rung** (Johnson & Kienholz 1982). It needs only the real undamped eigensolve plus a per-element strain-energy split — no complex eigenproblem. Its near-real-modes assumption holds *better* for a stiff lossy core (EG, E ≈ 30–45 GPa, η ~1e-2 class) than for the soft-VEM constructions it was invented for. The complex/QEP path stays behind bookmark #3831 (untriggered).
- **The substrate is mostly landed.** The v0_5 anisotropic-heterogeneous foundations (#3777–#3782) shipped a generic solver core (`MaterialField`, `ConstantField`, `DiscreteCellField`, `element_stiffness_*_with_field`) and a live author-reachable `Field<Point3<Length>, AnisotropicMaterial>` overload of `solve_elastic_static` — consumed today only by the FDM as-printed producer. `Mode.damping_ratio` already exists and is consumed downstream (transient integrator), so MSE is a new value *source* for an existing field, not a result-model change.
- **The gaps are narrow**: `classify_material` hardcodes its heterogeneous branch to `FieldSourceKind::AsPrintedZones` (any other well-typed Field fails at eval with `ExpectedStructureInstance`); modal assembly (`assemble_modal_km`) still calls the legacy homogeneous `element_stiffness(&IsotropicElastic)` kernel rather than the `_with_field` path; no material carries a loss property; the synthetic dims-overload meshes know element centroids (the FDM path samples them) but have no layer-interface awareness.
- **No gmsh dependency.** The dims-overload synthetic meshes are hand-built; the whole PRD is decoupled from #6660 (body-arg meshing). Body-arg damped modal falls out later when #6660 lands, via the same shared dispatch.
- **Stiffness fidelity bonus:** the same bonded path in *static* solves replaces the printer's homogenised-material idiom, fixing its known errors (shear path ~30–50% optimistic on stubby members, measured `pil_fea_vs_eb` 0.81; membrane EA ~60% overstated).

Fidelity honesty carried from the survey (documented, not solved here): the dominant error sources for a predicted ζ are (1) η input data — published EG-vs-steel multipliers span 4×–16× depending on measurement class (material coupon vs whole machine); (2) omitted joint/interface damping (bolted ζ 0.3–5% vs steel material η ~1e-3) — bookmark #6861; steady-state FRF response is bookmark #6860. Both bookmarks dep on this capability.

## Sketch of approach

Material description factors into three orthogonal layers, and this PRD extends each without collapsing them:

1. **Law** (what the material does; direction-dependent, position-free): a `Damped` mixin trait adds `loss_factor` to any constitutive family; `DampedMaterial : ElasticMaterial + Damped {}` is the ergonomic named intersection for the isotropic case. The resolved Rust value `AnisotropicMaterial` (built by `AnisotropicMaterial::from_law`) today carries only `{d_local, frame}` — verified 2026-08-27, density is dropped at resolution (harmless for K-only statics, fatal for a heterogeneous mass matrix). It gains **both** `eta: f64` (0.0 for non-damped laws) and `rho: f64` (from the law's `density` param) so per-element sampling carries loss and mass exactly as it carries stiffness.
2. **Field** (which law applies where): `classify_material` is generalized from its `AsPrintedZones`-only branch to accept **any** `Field<Point3<Length>, AnisotropicMaterial>` source evaluable at element centroids. The **author surface** is the new declarative `LayeredZones`-style source produced by the convenience constructors `sandwich_material` / `material_zones` (trampoline-built, the `as_printed_material` pattern); declarative sources are introspectable, so the dims-overload mesh generators snap element planes to declared layer interfaces. `Analytical` acceptance is engine-level (exercised by Rust-built fields in tests) — raw author lambdas are blocked upstream by #6871 and are out of scope here.
3. **Damping model selection** (explicit, never implicit): a third `DampingDescriptor`, `MaterialDamping { param extra : DampingDescriptor = NoDamping() }`, selects MSE. Composition is additive and explicit: ζ_mode = ζ_MSE + ζ_extra(ω_mode); `NoDamping`/`RayleighDamping` behave byte-identically to today. `extract_damping` (single consumption point, nominal type-name dispatch) gains one arm.

Modal goes heterogeneous by moving `assemble_modal_km` onto the same `_with_field` per-element entry points `solve_elastic_static` uses, plus a Field overload of `modal_analysis`. MSE itself is a cheap post-process: element matrices are pure functions of the retained mesh + material samples, so per-mode SE_e = ½·φᵀK_eφ is recomputed per element and combined as ζ_mode = ½·Σ η_e·SE_e / Σ SE_e — **no bucketing needed for the ratio** (per-element η suffices); per-material SE *shares* are grouped (by zone for declarative sources) only for the diagnostics surface.

Engine-integration seam (G1 sub-check): every runtime mechanism here rides the existing §3.4 ComputeNode dispatch of `engine-integration-norm.md` — the `@optimized("solver::elastic_static")` / modal trampolines and the `fdm::as_printed_material_r_fast` producer precedent. No new seam is introduced.

## Resolved design decisions

1. **`Damped` mixin + `DampedMaterial` named intersection** (not a `loss_factor` param on `ElasticMaterial`, not `Option<Real>`): check-time honesty ("haven't considered damping" is a *type*, not a sentinel value), zero migration (ElasticMaterial contract and its exact-member-count tests untouched; a DampedMaterial *is* an ElasticMaterial everywhere), and the mixin composes with future non-isotropic damped laws. Probed green 2026-08-27: user trait declaration, multi-conformance, trait-typed params, multi-parent refinement (`trait X : ElasticMaterial + Damped {}`) all check clean; anonymous `param m : A + B` is a parse error (spelled as the named trait instead). Naming hazard, handled not ignored: an unrelated `trait Damping : MaterialSpec { param damping_ratio; param loss_factor }` already exists in `materials_mechanical.ri` (datasheet-spec family, not ConstitutiveLaw) — α adds cross-reference comments in both files and ι's discoverability acceptance explicitly disambiguates the two. Known wart, not a blocker: #6870 — member access through a *trait-typed* param currently erases dimensions to Real; `loss_factor : Real` is immune (dimensionless), solve trampolines read raw values in Rust, and the exemplar binds concrete instances.
2. **All four stdlib presets conform to `DampedMaterial`** with literature loss factors + `loss_factor_provenance` (preset-level convention, matching the existing per-field provenance pattern). η values carry ranges and amplitude-dependence caveats in provenance notes.
3. **Explicit damping-model descriptor** (`MaterialDamping`), never an implicit rule for "materials carry η AND Rayleigh given": composition is opt-in via `MaterialDamping(extra: RayleighDamping(…))`, additive in ζ. Additive superposition of independent loss mechanisms is standard practice and gives non-material losses (joints — #6861) a labelled home. A `MaterialDamping` solve over materials none of which are `Damped` fails **loudly** at eval, naming the material and the fix (conform to `DampedMaterial`); silent 0.0 is forbidden.
4. **General field acceptance at the engine seam; declarative constructors as the author surface.** The fundamental dispatch accepts any evaluable Field source (the type surface was always general; the restriction was one `if let`). `sandwich_material` / `material_zones` return a *declarative* source kind so layer geometry is introspectable; they enforce well-formedness in-construction (layer thicknesses sum to the section; zones cover) so gaps are unrepresentable. **Substrate-probe amendment (2026-08-27, pre-decompose):** raw `fn_field` material lambdas were found unauthorable at the type layer — a parameterized annotation (`|p : Point3<Length>|`) does not resolve, and lambda-param member access (`p.z`) is unsupported, so no coordinate-dependent body can be written; the unannotated form infers `Field<Real, _>` and misses the overload loudly at check time. Both gaps are filed as #6871 (general analytic-field expressiveness, not damping-specific); the committed negative fixture `tests/prd-gate/fixtures/raw_lambda_material_field_rejected.ri` pins the rejection, and follow-on #6872 (dep-gated on #6871 + γ) flips it and brings the raw-lambda author surface into scope when the blockers land.
5. **Mesh-interface snapping is required for honest MSE on sandwiches** (a 3mm skin must not share an element with core material): the dims-overload mesh generators accept interface planes from declarative sources and align element boundaries to them. Without alignment, centroid sampling smears layers and the SE split is mush — this is a correctness feature, not an optimization.
6. **Scope = dims-overload (synthetic-mesh) path only** for solves. Body-arg (`Solid`) damped modal is out of scope, gated on #6660; the dispatch built here is shared, so it falls out there without redesign.
7. **Do not bake the spec's "5–10× steel" into any gate (G6).** Worked analytic caution: for pure bending of a 3/16/3 sandwich (steel skins, EG core E≈30 GPa), the core's flexural strain-energy share is only ≈8%, giving eta_mode ≈ 0.0034 with η_EG=0.03/η_steel=0.001 — a ≈3.4× ratio *before* shear participation raises it (independently re-derived at review: 8.3–8.6% share, ratio 3.4×). The EG-filled box-section pillar is higher: fill-vs-steel flexural EI split gives EG share ≈24%, ratio ≈7.8× pure-bending. The 5–10× claim is an *open engineering question this capability exists to answer* (in the printer design, with real geometry); the exemplar's ratio cells gate defensible bands — panel [3.0, 25] (floor = analytic 3.4 minus discretization margin; shear only raises it), pillar [5, 25] — never the aspirational spec number as such.
8. **Per-element MSE, zone-grouped diagnostics.** ζ_mode needs only per-element η; SE shares (per distinct material/zone, per mode) are exposed as diagnostics because the *shares* are the design insight (how much energy the core actually captures — the CLD question itself).
9. **Assembly-derived material fields are the target producer** (north-star): each sub contributing body + material, the union solved as one heterogeneous field — multi-body bonded assemblies without hand-written fields. Perfect bond ≡ single continuous body with piecewise material, so this PRD's field path *is* the bonded-assembly solve v1; the derivation producer is a dep-gated `[MILESTONE]` capstone (leaf μ) on this PRD's field surface + the assembly-derivation chain (#6626) + #6660, escalating for a human PRD decision when its deps land. Bond-line compliance/loss modelling stays out of scope (bookmark #6861 carries it).

## Contract (B+H — load-bearing seams: FEA + ComputeNode dispatch)

**C1. Damped law surface.** `trait Damped { param loss_factor : Real }` (dimensionless, ≥ 0, hysteretic loss factor η; ζ ≈ η/2 at resonance). `trait DampedMaterial : ElasticMaterial + Damped {}`. Conformers declare both parents' params; presets add `loss_factor_provenance` by the existing convention. The resolved `AnisotropicMaterial` is extended to `{d_local, frame, rho, eta}`: classification/field-build populates `rho` from the law instance's `density` param and `eta` from `Damped` conformance (else 0.0). Every existing constructor site is migrated in the same change (rustc is the structural guard); elastostatic behaviour is unaffected (`rho`/`eta` unread on that path).

**C2. Field classification.** `classify_material` accepts any `Value::Field` whose codomain resolves to `AnisotropicMaterial`, keyed by source kind: `AsPrintedZones` (unchanged), `Analytical` (lambda evaluated at element centroids), declarative layered/zones (introspectable breakpoints + per-zone laws). Non-material codomain or unevaluable source → loud eval error naming the source kind. Semantics: each element's material is the field evaluated at that element's centroid; declarative sources additionally publish interface planes to the mesh generator (C3).

**C3. Layered synthetic mesh.** The dims-overload mesh generators accept an ordered list of interface coordinates along a named axis; generated element boundaries include every interface plane exactly (no element straddles an interface). Raw `Analytical` sources publish no planes — sampling proceeds on the unsnapped grid and the docs state the caveat. Grading: at least one element per declared layer; a layer thinner than the default grid pitch forces local subdivision. P2 promotion composes for free: once P1 planes are snapped, every tet lies within one layer, so its edges (convexity) and therefore `promote_beam_mesh_to_p2`'s edge-midpoint nodes stay in-layer — no P2-level snapping work exists.

**C4. Heterogeneous modal assembly.** `assemble_modal_km` gains a field-driven path built on the `_with_field` per-element stiffness entry points — **explicitly including `element_stiffness_p2_with_field`** (which exists and is bit-verified against the legacy P2 path, but is test-only today; ζ wires it into production). Do NOT mirror the elastostatic dims path here: that path is P1-only (P2 volume meshes degrade to `None`), and P1 on slender beams hits the bending-lock hazard (9–11% error vs P2's ~1%, this repo's own `modal_benchmarks` record) — the ζ/B6 bounds are achievable only at P2, via `promote_beam_mesh_to_p2` exactly as the homogeneous modal path does today. The mass matrix gains its first per-element-density path (none exists anywhere today), reading the resolved value's `rho` (C1); note `extract_density` currently returns 0.0 for `Value::Field` materials — a latent defect on the heterogeneous static path (masked because statics builds no mass matrix) that γ fixes at the same seam. The homogeneous path remains byte-identical (regression-gated). `modal_analysis` gains a Field-material overload mirroring `solve_elastic_static`'s.

**C5. MSE damped modal.** Under `MaterialDamping`: after the (unchanged, real, undamped) eigensolve, for each mode i: SE_e = ½·φᵢᵀK_eφᵢ per element (recomputed from retained mesh + samples), ζᵢ = ½·(Σ_e η_e·SE_e)/(Σ_e SE_e) + ζ_extra(ωᵢ), where ζ_extra is the `extra` descriptor's Rayleigh formula (0 for `NoDamping`). `Mode.damping_ratio` carries ζᵢ; per-zone SE shares per mode are exposed as diagnostics (shape: Open question 1). Degenerate identity: a single-material model yields ζᵢ = η/2 exactly (energy ratio ≡ 1 by construction, to fp rounding). `NoDamping` / bare `RayleighDamping` paths byte-identical to pre-PRD.

**C6. Failure semantics.** `MaterialDamping` + any element whose law lacks `Damped` → eval error (name the material type; no silent 0). Declarative constructor mis-stacks (layers ≠ section thickness; overlapping zones) → check/eval-time constraint failure at the constructor, not downstream.
