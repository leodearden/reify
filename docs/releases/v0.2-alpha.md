# Reify v0.2-alpha

The first Reify release you can install without building from source.

- **Installers.** A `.deb` (`Reify_<version>_amd64.deb`, which puts the `reify` CLI on your `PATH`) and an AppImage, both for Ubuntu 24.04 on x86_64. Each carries its own OpenCASCADE, gmsh, OpenVDB and oneTBB. See the Install section of the README.
- **Start view.** `reify-gui` with no file opens a launcher: Open, New, Recent, and a Mode choice.
- **Edges in black.** The viewport can switch to an edges-in-black view.
- **The first alpha user's four issues are fixed:** #1, the tree-sitter grammar is always generated at ABI 14 (task 9727); #2, `setup-dev.sh` installs the GUI sidecar's npm dependencies (task 9728); #3, the release GUI build enables `tauri/custom-protocol` so the window renders (task 8116); #4, the sidecar bundles its runtime dependencies (task 9729).

Closes: #1, #2, #3, #4

## Breaking changes since v0.1-alpha

Each change below makes a file that `reify check` accepted at v0.1-alpha fail now. Every entry shows the old form, the error lines `reify check` prints for it, and the fixed form. Both snippets are committed files under `tests/prd-gate/fixtures/`, and `tests/infra/test_migration_note_v0_2.sh` checks that each old form fails with exactly the quoted errors and each fixed form passes. `reify check` prints the message, and only a few messages spell out their code, so each entry also names the diagnostic code behind it, or says the diagnostic is uncoded.

Most entries are one rule: **a number that stands for a physical quantity must carry its unit.** At v0.1-alpha a bare number in a length slot meant metres (SI base), so a mechanical fix that keeps your geometry writes the same value in a unit, for example `0.005` as `5mm`. Angles are the exception; see "Angles need a unit".

The changes, in order:

- A bare `Scalar` is no longer a type
- A dimensioned parameter or `let` needs a dimensioned initializer
- A constructor argument must match the field's type
- A misspelled constructor argument is an error
- A constraint argument must carry its parameter's unit
- Comparing a length with a bare number is an error
- Geometry builtins need dimensioned lengths
- Angles need a unit
- A transform's translation must be a length
- A geometry input with no value fails `reify check`
- A `connect` runs from an `out` port to an `in` port
- An objective that nothing can move is an error
- A trait body cannot declare a port
- `Physical` takes a `geometry` and a `material`
- `Strong` members are pressures, and `uts` is `ultimate_tensile_strength`
- `not` is a keyword

### A bare `Scalar` is no longer a type

`Scalar` with no dimension is rejected wherever a type is written (task 4375, `docs/prds/v0_6/real-dimensionless-unification.md`).

Code: `E_BARE_SCALAR` (`DiagnosticCode::BareScalarType`).

```text
error: bare `Scalar` is not a valid type: write `Scalar<Q>` or a named dimension like `Length`
```

Before (`tests/prd-gate/fixtures/migration_v0_2_bare_scalar_before.ri`):

```
structure def Bracket {
    param width: Scalar = 80mm
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_bare_scalar_after.ri`):

```
structure def Bracket {
    param width: Length = 80mm
}
```

**Fix:** Write the named dimension (`Length`, `Angle`, `Pressure`, ...) or `Scalar<Q>`. For a plain dimensionless number, write `Real`.

### A dimensioned parameter or `let` needs a dimensioned initializer

The declared type and the initializer must agree in dimension, for parameter defaults (task 4318) and for annotated `let` bindings (task 4705), so a bare number no longer initializes a `Length`.

Code: `E_PARAM_DEFAULT_TYPE_MISMATCH` (`DiagnosticCode::ParamDefaultTypeMismatch`) and `E_LET_ANNOTATION_TYPE_MISMATCH` (`DiagnosticCode::LetAnnotationTypeMismatch`).

```text
error: parameter 'width' declared `Scalar[m]` but its initializer evaluates to `Real`; declared type and initializer dimension must agree
error: let binding 'depth' declared `Scalar[m]` but its initializer evaluates to `Real`; declared type and initializer type must agree
```

Before (`tests/prd-gate/fixtures/migration_v0_2_dimensioned_initializer_before.ri`):

```
structure def Seal {
    param width: Length = 0.005
    let depth: Length = 0.002
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_dimensioned_initializer_after.ri`):

```
structure def Seal {
    param width: Length = 5mm
    let depth: Length = 2mm
}
```

**Fix:** Write the unit. A bare length meant metres (SI base), so `0.005` is `5mm`.

### A constructor argument must match the field's type

Structure constructors check each named argument against the field it binds (struct-constructor conformance, tasks 5306 and 5763; the hint comes from task 5750).

Code: `E_ARG_TYPE_MISMATCH` (`DiagnosticCode::ArgTypeMismatch`).

```text
error: argument 'thickness' has type 'Real' but param 'thickness' requires type 'Scalar[m]'; pass a dimensioned Length literal such as `1m`
```

Before (`tests/prd-gate/fixtures/migration_v0_2_ctor_field_type_before.ri`):

```
structure def Plate {
    param thickness: Length = 2mm
}

structure def Stack {
    let p = Plate(thickness: 0.003)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_ctor_field_type_after.ri`):

```
structure def Plate {
    param thickness: Length = 2mm
}

structure def Stack {
    let p = Plate(thickness: 3mm)
}
```

**Fix:** Write the unit. A bare length meant metres, so `0.003` is `3mm`.

### A misspelled constructor argument is an error

A named argument that matches no parameter of the structure is reported (code added by task 5303, made an error by task 5306).

Code: `E_CTOR_UNKNOWN_FIELD` (`DiagnosticCode::CtorUnknownField`).

```text
error: E_CTOR_UNKNOWN_FIELD: unknown named argument 'thicknes' in call to 'Plate'; 'Plate' has no parameter with that name
```

Before (`tests/prd-gate/fixtures/migration_v0_2_ctor_unknown_field_before.ri`):

```
structure def Plate {
    param thickness : Length = 2mm
}

structure def Bracket {
    param plate : Plate = Plate(thicknes: 5mm)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_ctor_unknown_field_after.ri`):

```
structure def Plate {
    param thickness : Length = 2mm
}

structure def Bracket {
    param plate : Plate = Plate(thickness: 5mm)
}
```

**Fix:** Correct the argument name to the parameter's.

### A constraint argument must carry its parameter's unit

Arguments to a `constraint def` are checked against its parameter types (task 4546).

Code: `E_CONSTRAINT_ARG_TYPE` (`DiagnosticCode::ConstraintArgTypeMismatch`).

```text
error: type mismatch: argument 'min' for constraint 'MinWall' has type Real but parameter expects Scalar[m]
```

Before (`tests/prd-gate/fixtures/migration_v0_2_constraint_arg_unit_before.ri`):

```
constraint def MinWall {
    param wall: Length
    param min: Length
    wall >= min
}

structure def Box {
    param thickness: Length = 3mm
    constraint MinWall(wall: thickness, min: 0.002)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_constraint_arg_unit_after.ri`):

```
constraint def MinWall {
    param wall: Length
    param min: Length
    wall >= min
}

structure def Box {
    param thickness: Length = 3mm
    constraint MinWall(wall: thickness, min: 2mm)
}
```

**Fix:** Write the unit. A bare length meant metres, so `min: 0.002` is `min: 2mm`.

### Comparing a length with a bare number is an error

Both sides of a comparison must have the same dimension (task 4490, compile-time operand checks).

Code: `DiagnosticCode::DimensionMismatch` (it has no `E_` mnemonic).

```text
error: dimension mismatch in comparison: Scalar[m] vs Real
```

Before (`tests/prd-gate/fixtures/migration_v0_2_comparison_unit_before.ri`):

```
structure def Box {
    param thickness: Length = 3mm
    constraint thickness > 0.002
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_comparison_unit_after.ri`):

```
structure def Box {
    param thickness: Length = 3mm
    constraint thickness > 2mm
}
```

**Fix:** Write the unit on the number. A bare length meant metres, so `0.002` is `2mm`.

### Geometry builtins need dimensioned lengths

The length slots of the geometry builtins reject a bare number (the units length gate, `docs/prds/v0_6/units-length-gate-completion.md`; `box`, `cylinder` and `sphere` were retyped by task 6450).

Code: `E_ARG_TYPE_MISMATCH` (`DiagnosticCode::ArgTypeMismatch`).

```text
error: sphere: radius argument expects Length, got Real; pass a dimensioned length such as `5mm`
```

Before (`tests/prd-gate/fixtures/migration_v0_2_geometry_length_unit_before.ri`):

```
structure def Ball {
    let body = sphere(0.005)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_geometry_length_unit_after.ri`):

```
structure def Ball {
    let body = sphere(5mm)
}
```

**Fix:** Write the unit. A bare length meant metres, so `sphere(0.005)` is `sphere(5mm)`.

### Angles need a unit

The angle slot of `rotate` rejects a bare number (task 5782; the migration is tracked in `docs/notes/angle-literal-migration-ledger.md`).

Code: `E_ARG_TYPE_MISMATCH` (`DiagnosticCode::ArgTypeMismatch`).

```text
error: rotate: angle argument expects Angle, got Real; pass a dimensioned angle such as `45deg` or `1.5rad`
```

Before (`tests/prd-gate/fixtures/migration_v0_2_geometry_angle_unit_before.ri`):

```
structure def Spun {
    let b = box(10mm, 10mm, 10mm)
    let spun = rotate(b, 0, 0, 1, 0.5)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_geometry_angle_unit_after.ri`):

```
structure def Spun {
    let b = box(10mm, 10mm, 10mm)
    let spun = rotate(b, 0, 0, 1, 0.5rad)
}
```

**Fix:** Write the unit the old number meant. At v0.1-alpha `rotate` read a bare angle as **radians**, so `0.5` is `0.5rad`, not `0.5deg`. `circular_pattern` read its bare angle as degrees, so a `360` there is `360deg`.

### A transform's translation must be a length

`transform_log` rejects a transform whose translation is dimensionless: a twist's linear half is a `Vector3<Length>` (RULING #6126, task 6126).

Code: `E_DIMENSIONED_ARG_REJECTED` (`DiagnosticCode::DimensionedArgRejected`).

```text
error: transform_log: a Transform's translation must be Vector3<Length>; got dimensionless (a twist's `linear` half carries Length — RULING #6126)
```

Before (`tests/prd-gate/fixtures/migration_v0_2_transform_translation_length_before.ri`):

```
structure def Pose {
    let twist = transform_log(transform3(orient_identity(), vec3(0.001, 0.002, 0.003)))
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_transform_translation_length_after.ri`):

```
structure def Pose {
    let twist = transform_log(transform3(orient_identity(), vec3(1mm, 2mm, 3mm)))
}
```

**Fix:** Write the translation in units. A bare length meant metres, so `vec3(0.001, 0.002, 0.003)` is `vec3(1mm, 2mm, 3mm)`.

### A geometry input with no value fails `reify check`

A parameter with no default that feeds a geometry builtin leaves that geometry unresolved. `reify check` used to print this error and still exit 0; since task 5404 burned its error-exit allowlist to zero, it exits 1.

Code: uncoded (the emitting site attaches no `DiagnosticCode`).

```text
error: failed to compile geometry operation: argument 'radius' for cylinder is unresolved (Undef)
```

Before (`tests/prd-gate/fixtures/migration_v0_2_undef_geometry_input_before.ri`):

```
structure def Bracket {
    param hole_d : Length
    let plate = box(80mm, 40mm, 5mm)
    let hole = cylinder(hole_d / 2, 5mm)
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_undef_geometry_input_after.ri`):

```
structure def Bracket {
    param hole_d : Length = 6mm
    let plate = box(80mm, 40mm, 5mm)
    let hole = cylinder(hole_d / 2, 5mm)
}
```

**Fix:** Give the parameter a default, or pass a value for it where the structure is used.

### A `connect` runs from an `out` port to an `in` port

Port direction is checked for dotted sub-port endpoints such as `b.inlet` (task 7175).

Code: uncoded.

```text
error: incompatible port directions for connect: In -> Out
```

Before (`tests/prd-gate/fixtures/migration_v0_2_connect_direction_before.ri`):

```
trait Flow { param diameter : Length }

occurrence def Pipe {
    port inlet : in Flow { param diameter : Length = 25mm }
    port outlet : out Flow { param diameter : Length = 25mm }
}

structure def Line {
    sub a = Pipe()
    sub b = Pipe()
    connect b.inlet -> a.outlet
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_connect_direction_after.ri`):

```
trait Flow { param diameter : Length }

occurrence def Pipe {
    port inlet : in Flow { param diameter : Length = 25mm }
    port outlet : out Flow { param diameter : Length = 25mm }
}

structure def Line {
    sub a = Pipe()
    sub b = Pipe()
    connect a.outlet -> b.inlet
}
```

**Fix:** Write the connection from the `out` port to the `in` port: `connect a.outlet -> b.inlet`.

### An objective that nothing can move is an error

A `minimize` or `maximize` whose expression reads no `auto` parameter has nothing to optimise and is rejected (task 5417).

Code: `E_OBJECTIVE_INERT` (`DiagnosticCode::ObjectiveInert`).

```text
error: E_OBJECTIVE_INERT: the `minimize` declared in `Plate` reads only `Plate.thickness`, which is never `auto` anywhere in `Plate` — so no solver variable can change its value and the objective has nothing to optimise. Declare `Plate.thickness` `auto` (e.g. `= auto` in place of the literal default) to make the objective effective, or remove the objective.
```

Before (`tests/prd-gate/fixtures/migration_v0_2_objective_inert_before.ri`):

```
structure def Plate {
    param thickness : Length = 4mm
    constraint thickness >= 2mm
    minimize thickness
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_objective_inert_after.ri`):

```
structure def Plate {
    param thickness : Length = 4mm
    constraint thickness >= 2mm
}
```

**Fix:** Remove the objective, or make the parameter it reads `auto`.

### A trait body cannot declare a port

At v0.1-alpha the parser silently dropped a `port` inside a `trait`. Since task 7809 that parse error is reported.

Code: uncoded (a parse error).

```text
Parse error: 3:13: syntax error in trait body
```

Before (`tests/prd-gate/fixtures/migration_v0_2_trait_body_port_before.ri`):

```
trait Sized {
    param size : Length
    port output : out Sized
}

structure def Block : Sized {
    param size : Length = 50mm
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_trait_body_port_after.ri`):

```
trait Sized {
    param size : Length
}

structure def Block : Sized {
    param size : Length = 50mm
}
```

**Fix:** Delete the port from the trait, and declare it on the structure or occurrence that has it.

### `Physical` takes a `geometry` and a `material`

The prelude trait `Physical` was rewritten to its spec shape (task 3603): it requires `param geometry : Solid` and `param material : Material`, and derives mass and centroid from them. The flat `name`, `density`, `volume` and `centroid_x`/`_y`/`_z` members are gone.

Code: `E_UNRESOLVED_NAME` (`DiagnosticCode::UnresolvedName`) and `DiagnosticCode::MissingRequiredMember`.

```text
error: unresolved name: geometry
error: unresolved name: material
error: unresolved name: geometry
error: missing required member 'geometry' (expected type: Geometry)
error: missing required member 'material' (expected type: Material)
error: unresolved name: material
```

Before (`tests/prd-gate/fixtures/migration_v0_2_physical_trait_before.ri`):

```
structure def Beam : Physical {
    param name : String = "beam"
    param density : Real = 7850.0
    param volume : Real = 0.002
    param centroid_x : Real = 0.0
    param centroid_y : Real = 0.0
    param centroid_z : Real = 0.0
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_physical_trait_after.ri`):

```
structure def Beam : Physical {
    param geometry : Solid = box(100mm, 20mm, 1000mm)
    param material : Material = Material(name: "steel", density: 7850kg/m^3, youngs_modulus: 200GPa)
}
```

**Fix:** Replace the flat members with a `geometry` and a `Material(...)` value. Material properties are dimensioned too: `density: 7850kg/m^3`, `youngs_modulus: 200GPa`.

### `Strong` members are pressures, and `uts` is `ultimate_tensile_strength`

The prelude trait `Strong` types its members as `Pressure` (task 3111), and `uts` was renamed `ultimate_tensile_strength` (task 4240).

Code: `DiagnosticCode::TypeMismatchForTraitMember`, `DiagnosticCode::MissingRequiredMember` and `E_UNRESOLVED_NAME` (`DiagnosticCode::UnresolvedName`).

```text
error: type mismatch for trait member 'yield_strength': expected Scalar[kg·m^-1·s^-2], got Real
error: missing required member 'ultimate_tensile_strength' (expected type: Scalar[kg·m^-1·s^-2])
error: type mismatch for trait member 'compressive_strength': expected Scalar[kg·m^-1·s^-2], got Real
error: unresolved name: ultimate_tensile_strength
```

Before (`tests/prd-gate/fixtures/migration_v0_2_strong_trait_before.ri`):

```
structure def Steel : Strong {
    param yield_strength : Real = 250000000.0
    param uts : Real = 400000000.0
    param compressive_strength : Real = 250000000.0
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_strong_trait_after.ri`):

```
structure def Steel : Strong {
    param yield_strength : Pressure = 250MPa
    param ultimate_tensile_strength : Pressure = 400MPa
    param compressive_strength : Pressure = 250MPa
}
```

**Fix:** Type the members `Pressure` and write their unit (a bare number meant pascals, so `250000000.0` is `250MPa`), and rename `uts`.

### `not` is a keyword

`not` became the keyword logical-not operator (task 3920), so an expression that mentions `not` now parses it as the operator. A parameter named `not` can still be declared but can no longer be read.

Code: uncoded (a parse error).

```text
Parse error: 3:19: invalid let: let open = not
```

Before (`tests/prd-gate/fixtures/migration_v0_2_not_keyword_before.ri`):

```
structure def Gate {
    param not : Bool = false
    let open = not
}
```

After (`tests/prd-gate/fixtures/migration_v0_2_not_keyword_after.ri`):

```
structure def Gate {
    param inverted : Bool = false
    let open = inverted
}
```

**Fix:** Rename the identifier, for example to `inverted`, at its declaration and at every use.

## Coming in v0.3-alpha

Two larger breaking changes are decided and planned for v0.3-alpha, which will carry its own migration note. Both PRDs are active, not finished:

- **Direction typing** (`docs/prds/v0_6/direction-typing.md`): one `Direction` type, written `dir(x, y, z)`, with explicit conversion to and from vectors. Builtins that take an axis or normal accept only a `Direction`, so the scalar forms are retired: `rotate(b, 0, 0, 1, 0.5rad)` from "Angles need a unit" becomes `rotate(b, dir(0, 0, 1), 0.5rad)`.
- **Stdlib namespace** (`docs/prds/v0_6/stdlib-namespace.md`): standard-library names are reached through an explicit `import std.X`, with strict visibility.

You can prepare for the second now: `reify fix --imports <file>` already ships in this release and adds the `import std.X` lines a file needs, and `reify fix --imports --check <file>` reports them without writing.
